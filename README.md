## Сайт

Статический многостраничный сайт с 10 направлениями продукции, разделами российской техники, услуг, заказчиков, компании, проектов, документов и контактов. HTML генерируется заранее; содержание доступно без JavaScript. Шрифты и изображения размещены локально.

Генератор поддерживает собственный SMTP-обработчик на основном домене и статическую копию без сбора заявок. На GitHub Pages размещается ссылка на основной сайт; FormSubmit и Яндекс Формы исключены. SMTP-секреты в репозитории отсутствуют. Фактический статус опубликованных версий — в [docs/deployment.md](docs/deployment.md).

Реквизиты и настройки обработки находятся в `site.json`, тексты политики, согласия и условий покупки — в `legal.py`. Страницы `/privacy/`, `/consent/` и `/buyers/` доступны из подвала. Полный текст подтверждённого согласия, версия и контрольная сумма добавляются в письмо с заявкой; PHP проверяет версию перед отправкой.

`legalDetailsConfirmed: true` отражает подтверждение владельцем реквизитов, адреса возвратов, графика и хранения заявок в Mail.ru. `contactFormEnabled: false` выключает поля формы и приём через PHP в новом пакете. Включение допускается после подачи уведомления РКН и выполнения организационных мер, включая порядок хранения и удаления писем. Порядок — в [docs/personal-data.md](docs/personal-data.md). Публикация кода не заменяет эти действия компании.

Проекты сохраняют явные пометки о демонстрационном характере. Локальная и GitHub-копии имеют `noindex`; основная SEO-сборка открывает 17 страниц. Аналитика и рекламные кампании выключены.

## Персональные данные и подготовка к рекламе

Локализация почты, баз, журналов и резервных копий подтверждается по договорам провайдеров. Компания определяет сроки и выполняет удаление писем, вложений и копий. PHP автоматически очищает только технические состояния и временные файлы. На хостинге следует настроить планировщик обслуживания.

Метрика загружается только при заданном счётчике и отдельном разрешении посетителя; отказ не влияет на доступность формы. Перед подключением аналитики или рекламы требуется проверить соответствующие документы и основания. Разрешение отвечать на заявку не является согласием на рекламные рассылки.

## Просмотр локально

Требуется Python 3.12 или новее.

```sh
python3 build.py
python3 verify.py
python3 -m http.server 4187 --bind 127.0.0.1 --directory dist
```

Откройте `http://127.0.0.1:4187/`.

## Публикация

GitHub Actions публикует сайт на GitHub Pages при каждом push в `main`. В Settings → Pages выбран источник GitHub Actions. Workflow получает адрес и префикс из настроек Pages: ссылки работают как по адресу проекта, так и после подключения собственного домена.

- `build.py`: содержимое и генератор страниц.
- `site.json`: основные сведения и обработчик формы.
- `dist/`: локальный сайт, стили, JavaScript и статические ресурсы.
- `verify.py`: заголовки, метаданные, ссылки и якоря.
- `.github/workflows/pages.yml`: автоматическая сборка и публикация.

Пример отдельной сборки для адреса проекта:

```sh
OUTPUT_DIR=_site BASE_PATH=/ligus-msk SITE_URL=https://asnarskiy.github.io/ligus-msk python3 build.py
OUTPUT_DIR=_site BASE_PATH=/ligus-msk python3 verify.py
```

## Домен

Домен направлен на REG.RU. HTTPS проверен; HTTP и www перенаправляются на https://ligus-msk.ru с кодом 308. MX, SPF, DKIM и другие записи почты при загрузке сайта не менялись.

## Графика

Логотип — самостоятельный SVG с прозрачным фоном, нарисованными кириллическими буквами и сквозными каналами. Он выполнен по типографическому референсу заказчика, в ультрамарине и без знака TM. Иллюстрации оборудования и первого экрана созданы с помощью ImageGen. Фотография оборудования иллюстративная и не подтверждает ассортимент или включение моделей в реестр.

Обложка для ссылок находится в `dist/og.png`. Общие Open Graph и Twitter Card метаданные добавляются генератором на все страницы; заголовок и описание соответствуют каждой странице. Абсолютный адрес изображения строится из `SITE_URL`, размеры считываются из PNG, а хеш файла в URL обновляет адрес при замене обложки. Для новой обложки замените PNG и запустите сборку. В `robots.txt` разрешён обход страниц, чтобы роботы могли прочитать директивы `noindex`. Включение индексации управляется `INDEXING_ENABLED`; по умолчанию она выключена.

Шрифт Manrope используется по SIL Open Font License, копия лицензии находится в `dist/assets/OFL-Manrope.txt`.

## SEO опубликовано, реклама подготовлена к подключению

[Пакет подключения](marketing/START.md): карта метаданных, три рекламных набора с 12 группами, 71 фразой, 48 заголовками и 36 текстами, TSV для Коммандера, цели и UTM. Подробный статус — в этом документе. Аккаунты, ставки и бюджет пока не настроены.

- `seo.py`, `marketing/seo-pages.json`: canonical, микроразметка, управление индексацией и sitemap.
- `dist/analytics.js`: выбор аналитики и цели без передачи полей заявки.
- `scripts/prepare_marketing.py`: проверка и экспорт рекламных черновиков.
- `scripts/check_marketing.mjs`: браузерная проверка с тестовыми ответами аналитики и SMTP.

Сборка с `INDEXING_ENABLED=1` открывает только 17 подготовленных страниц основного домена. GitHub-копия, служебные страницы и демонстрационные проекты не индексируются. Без `METRICA_ID` нет запросов к Метрике. Для повторной публикации основной SEO-версии используйте `INDEXING_ENABLED=1 python3 scripts/build_hosting.py --layout regru`. Метрика подключается независимо и пока выключена.
